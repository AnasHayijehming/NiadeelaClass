  • เพิ่มการ์ดเกมในแกลเลอรีและตรวจเส้นทางผ่านเว็บเซิร์ฟเวอร์จริง
  • ตรวจหน้าเริ่ม เกมเพลย์ และการแสดงผลทั้งเดสก์ท็อปกับมือถือ

การตัดสินใจที่ไม่มีในคำขอ

  • ชื่อเส้นทาง: ใช้ apps/ar-math-adventure/ ให้สั้นและสื่อถึงโหมด AR โดยตรง
  • ระดับชั้น: จัดเป็น ป.3–6 เพราะมีบวก/ลบเลข 2–3 หลัก และคูณ/หารแม่ 2–12
  • โหมดกล้อง: คง MediaPipe จาก CDN ตามต้นฉบับ แต่ต้องยืนยันว่าเมาส์/สัมผัสยังเล่นได้เมื่อกล้องหรือ CDN ใช้งานไม่ได้

ข้อแลกเปลี่ยน

  • ต้นฉบับเป็น vinext ที่ต้องเสิร์ฟผ่าน Worker จึงต้องแปลงผล build เป็นหน้า HTML สแตติกและแก้ asset path สำหรับ subfolder
  • ชุดทดสอบเดิมยังตรวจหน้า starter ที่ถูกลบแล้ว จึงไม่ใช่หลักฐานผ่านของตัวเกม; ใช้ build, lint และ browser QA เป็นเกณฑ์หลักแทน

สถานะ

นำเข้า ตรวจสอบ และพร้อมเผยแพร่

  • แก้ runtime preload ของ vinext ไม่ให้เติม / หน้า asset path ซึ่งเดิมทำให้ไฟล์ JavaScript 4 รายการตอบ 404 เมื่อวางใต้ subfolder
  • ตัดไฟล์ build ที่ไม่ได้ใช้งาน ได้แก่ manifest ภายใน ไฟล์ตัวอย่าง และ local font bundle ที่ CSS ไม่ได้อ้างถึง
  • ใช้ภาพหน้าเริ่มจริงเป็น thumbnail กลางร่วมกับการ์ดแกลเลอรี เพื่อลด asset ซ้ำซ้อน
  • คง HTML ที่ worker สร้างในรูป minified เพื่อรักษา RSC hydration payload ไม่จัดรูปแบบใหม่ด้วย formatter

ผลตรวจสอบ

  • source build ผ่าน และ ESLint ผ่าน; npm test ของต้นฉบับไม่ผ่านเพราะ script ใช้ syntax ตั้ง environment variable แบบ Unix บน Windows และ test ยังอ้าง starter skeleton ที่ไม่มีแล้ว
  • เกม hydrate สำเร็จ ไม่มี console error ใน session ปกติ และ asset ภายในโหลดจาก subfolder ครบ
  • เริ่มเกมโดยไม่ใช้กล้อง ตอบ 12 × 6 = 72 ถูก คะแนนเพิ่มเป็น 100 และไปข้อ 2
  • desktop 1440 × 900 และ mobile 390 × 844 แสดงผลครบ โดย mobile มี scrollWidth = innerWidth = 390
  • เมื่อจำลอง Google Fonts และ MediaPipe ตอบ 503 เกมยัง hydrate และเริ่มเล่นด้วยเมาส์/สัมผัสได้
  • ตัวกรองซ่อนเกมใน ป.1–2 และแสดงใน ป.3–4 กับ ป.5–6 ตามระดับที่กำหนด; เส้นทางเกมทั้งหมด 9 หน้าได้ HTTP 200
